# פרוטוקולי עבודה — איך זה בנוי

## הרעיון

כל לקוח עובר את [הפרוטוקול הכללי](general.md) של המשרד. בכרטיס הלקוח (`client.html`) הפרוטוקול מוצג לפי שלבים; כל תהליך מציג את המבצע האחראי, את זמן הביצוע כלשונו, ומועד יעד מחושב כשהתאריך שהוא תלוי בו ידוע. כל עובד מסמן וי על הפריטים שבתפקידו, ונשמר מי סימן ומתי.

- **מה עליי** (`clients.html#mine`): כל הפריטים הפתוחים של עובד אחד בכל הלקוחות, לפי דחיפות. מסמנים ישירות מהרשימה.
- **בקרה יומית** (`clients.html#control`): תהליכים 32 ו־33. כמה פתוח ובאיחור אצל כל עובד, ואילו לקוחות תקועים ואיפה.
- **משימות**: משימות אד־הוק (למשל מהשיחה השבועית, תהליך 31) עם מבצע ותאריך. מופיעות ב"מה עליי".

## כללים חשובים

- **מפתח של פריט לא משתנה אף פעם** (למשל `p04.address`). הסימונים נשמרים לפי המפתח. כדי לשנות ניסוח מספיק לשנות את `label`; כדי להחליף פריט, מוסיפים מפתח חדש.
- **תנאים לפי פרטי הלקוח**: סוג יום הצילום (נטלי / דניס, מישל וסמיון), מי מבצע את האפיון (אופיר / שיראל), האם יש לוגו, וסטטוס הלקוח. כשפרט חסר, התהליך מבקש להשלים אותו.
- **מועדים**: ימי עסקים הם א׳–ה׳. חגים עדיין לא נלקחים בחשבון. "יום לפני הצילום" הוא יום העסקים הקודם. זמן בלי תאריך עוגן לא מסומן כאיחור.
- **"לא רלוונטי"** סוגר פריט חובה בלי לסמן שבוצע, ומתועד בהיסטוריה. פריטים שמסומנים "אם רלוונטי" לא חוסמים השלמה של תהליך.

## הוספת פרוטוקול של עובד

כשמגיע פרוטוקול אישי של עובד:

1. שומרים אותו כ־`docs/protocols/<שם>.md` (תמלול נאמן, כמו `general.md`).
2. פריטים שמפרטים תהליך קיים מהפרוטוקול הכללי נוספים לאותו תהליך ב־`app/protocol.js`, עם `owners` של העובד. פריטים חדשים לגמרי נוספים כתהליך חדש בשלב המתאים.
3. מעלים את `PROTOCOL_VERSION`, מריצים `npm test` ו־`node tests/protocol-e2e.mjs`, ומפעילים את סוכן ה־QA (`.claude/agents/protocol-qa.md`) להשוואה מול המסמך.

לקוחות קיימים מקבלים את הפריטים החדשים כפתוחים; סימונים קיימים לא נמחקים.

## הקמה במסד הנתונים

להריץ את המיגרציה `20260929120000_client_protocol.sql` על פרויקט ה־Supabase (למשל ב־SQL Editor). כל עובד צריך משתמש ושורה בטבלת `staff` (ראו README הראשי). בכניסה הראשונה כל עובד בוחר מי הוא בפרוטוקול, והבחירה נשמרת בעמודה `staff.person`.
